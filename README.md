# sqliprobe

сканер своих сайтов на sql-инъекции. находит параметр, кидает пачку
проверочных пейлоадов, смотрит разницу в ответах и говорит где дыра
и какая субд за ней (по сигнатурам ошибок).

```
pip install -r requirements.txt
python -m sqliprobe.cli --url "http://localhost:8000/item?id=1" --consent
python -m sqliprobe.cli --url "http://localhost:8000/news" --consent --crawl
```

принимает любые ссылки: с `?id=` и без. без вопросика сам ищет точки:
ссылки с параметрами, get/post формы, числа в пути (`/news/5`).
флаг `--crawl` ходит по страницам своего же хоста.

## ⚠️ только свои сайты

запуск по чужим сайтам без письменного разрешения — это уголовка
(ст. 272 УК РФ / CFAA в зависимости от страны). тул без флага `--consent`
не сканирует, это осознанно. проверяй локалку, стейджинг, свои vps.

## что умеет (0.2.0)

- любые url: парсит страницу, находит ссылки с параметрами, формы, числа в пути
- POST-формы тестирует так же как GET
- `--crawl`: обход своего хоста с лимитом страниц
- error-based: кавычка/коммент, ловит sql-ошибки в ответе, определяет субд
- boolean-based: `AND 1=1` / `AND 1=2`, сравнивает страницы
- time-based: `SLEEP(5)`/`pg_sleep`, меряет задержку
- отчёт в консоль + `--json out.json`

## что не умеет

- не эксплуатирует (не сливает таблицы, это уже не сканер)
- js-рендер не выполняет (spa с api смотри через devtools и таскай url руками)
- waf/rate-limit обходит никак, просто стучится медленно (`--delay`)

## стенд для проверки

`python test-server.py` — локальная фейковая дыра (mysql-ошибка, boolean,
sleep). Гнать: `python -m sqliprobe.cli --url "http://127.0.0.1:8765/item?id=1" --consent --delay 0.1`
