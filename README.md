# sqliprobe

![version](https://img.shields.io/badge/version-1.0.0-blue)
![python](https://img.shields.io/badge/python-3.8%2B-3776ab)
![platform](https://img.shields.io/badge/platform-cross--platform-lightgrey)
![license](https://img.shields.io/badge/license-MIT-green)

**sqliprobe** — сканер SQL-инъекций для сайтов, которые принадлежат вам или проверяются
с письменного разрешения. Ищет точки в GET-параметрах, числах в пути, POST-формах и куках,
определяет СУБД по сигнатурам ошибок, подтверждает error-based находки повторным запросом
и не пытается эксплуатировать дыру: только детект.

```
Только свои сайты       --consent обязателен, без него запросов нет
Четыре техники          boolean, error, union, time — вместе или по отдельности
Поиск точек             GET, числа в пути, POST-формы, куки, обход ссылок
Меньше фейков           E подтверждается повтором, U — ошибкой ORDER BY
Отчёты и разведка       консоль, JSON, HTML, WAF-детект, заголовки и утечки
```

> ⚠️ **Только свои сайты.** Сканирование чужих сайтов без письменного разрешения — это
> неправомерный доступ, а не «проверка». `--consent` подтверждает, что сайт ваш или
> разрешение есть. Без флага сканер не делает ни одного HTTP-запроса.
> Подробнее — [docs/LEGAL.md](docs/LEGAL.md).

## Возможности

### Поиск точек

- GET-параметры целевой ссылки: `?id=1`, `?user=admin&page=2`;
- числа в пути: `/news/5`, `/item/42`;
- POST-формы на странице: поля перебираются по одному, остальные сохраняют исходные значения;
- куки, которые сервер выставил в ходе запросов;
- очередь ссылок того же хоста с параметрами, найденных на странице;
- `--crawl` — обход ссылок в ширину в пределах `--max-pages`.

### Техники

- **B — boolean-blind:** пары `AND 1=1` / `AND 1=2`, сравнение длины ответа;
- **E — error-based:** кавычки и битые конструкции, сигнатуры пяти СУБД и generic, повторный запрос для подтверждения;
- **U — union:** `ORDER BY 1..N`, по ошибке определяется число колонок;
- **T — time-based:** `SLEEP`, `pg_sleep`, `WAITFOR DELAY`, `BENCHMARK`;
- любая комбинация букв, по умолчанию все четыре: `BEUT`.

### WAF, тамперы и разведка

- определение Cloudflare, DDoS-Guard, Sucuri, Incapsula, ModSecurity, F5 BIG-IP и Akamai;
- проверка, режет ли WAF кавычки;
- мини-набор тамперов: `space2comment`, `randomcase`, `versioned`;
- аудит заголовков: `Server`, `X-Powered-By`, отсутствие CSP, HSTS, `X-Frame-Options`, `X-Content-Type-Options`;
- флаги кук: `HttpOnly`, `Secure`, `SameSite`;
- проверка `.git/HEAD`, `.env`, `robots.txt`, `sitemap.xml`;
- `--no-recon` отключает разведку.

### Отчёты

- консольный отчёт с целью, WAF, находками и recon;
- JSON с полным результатом: находки, параметры, пейлоады, СУБД, recon, WAF;
- HTML-таблица для быстрого просмотра;
- наглядное «ничего» вместо выдуманных находок.

## Как это работает

1. **Согласие.** Без `--consent` CLI печатает баннер, отказывается сканировать и возвращает код 2. Ни одного запроса до этой проверки не уходит.

2. **Разбор цели.** Из ссылки извлекаются GET-параметры, в пути ищутся числовые сегменты. Перед проверкой снимается базовый ответ: тело, статус и время.

3. **WAF.** Отдельная проба с кавычкой ищет признаки WAF по заголовкам `Server` и специальным заголовкам, а также смотрит, не блокируется ли запрос с кавычкой.

4. **Проверка параметров.** Для каждого GET-параметра, числового сегмента пути, поля POST-формы и куки по очереди применяются выбранные техники. Пейлоад подставляется только в одну точку, остальные параметры остаются исходными.

5. **Подтверждение.** Error-based находка отправляется ещё раз: если сигнатура ошибки или новый статус 500 повторяются, находка помечается `confirmed`. Union подтверждается ошибкой на `ORDER BY`.

6. **Формы, куки и очередь.** На уровне 2 и выше проверяются POST-формы, куки и ссылки с параметрами, найденные на странице. Очередь обрабатывается в `--threads` потоков.

7. **Обход.** С `--crawl` сканер идёт по ссылкам того же хоста в ширину и добавляет их в очередь, не выходя за `--max-pages`.

8. **Разведка и отчёт.** Если не указан `--no-recon`, проверяются заголовки, куки и типовые утечки. Результат печатается в консоль и, если попросить, сохраняется в JSON или HTML.

## Требования

- Python 3.8+;
- `requests` 2.31+ (единственная зависимость);
- доступ к проверяемому сайту;
- ничего собирать и компилировать не нужно.

Сканер кроссплатформенный: Linux, Windows, macOS. Браузер и JavaScript-движок не нужны — работа идёт по обычному HTTP.

## Установка

```sh
git clone https://github.com/palychdev/sqliprobe
cd sqliprobe
pip install -r requirements.txt
```

Пакет не публикуется в PyPI, отдельной команды `sqliprobe` в `PATH` нет. Запуск — из каталога проекта:

```sh
python -m sqliprobe.cli --help
```

## Быстрый старт

Сначала — локальный стенд из репозитория. В одном терминале:

```sh
python test-server.py
```

Во втором:

```sh
python -m sqliprobe.cli --url "http://127.0.0.1:8765/item?id=1" --consent --delay 0.1
```

После проверки стенда — свой сайт:

```sh
# GET-параметр
python -m sqliprobe.cli --url "https://your-site.example/item?id=1" --consent

# число в пути
python -m sqliprobe.cli --url "https://your-site.example/news/5" --consent

# обход ссылок своего хоста
python -m sqliprobe.cli --url "https://your-site.example/" --consent --crawl --max-pages 20
```

Для локального стенда задержку можно снизить до `0.1`, для боевого сайта лучше оставить дефолтную секунду.

## Командная строка

### Цель и темп

| Аргумент | Что делает |
|---|---|
| `--url URL` | цель: страница, ссылка с `?id=` или `/news/5`; обязательный аргумент |
| `--consent` | подтверждение, что сайт ваш или есть письменное разрешение; без него сканирования нет |
| `--delay SEC` | пауза между проверяющими запросами, по умолчанию 1.0 |
| `--timeout SEC` | таймаут HTTP-запроса, по умолчанию 15 |
| `-m FILE` | файл со списком URL; строки должны начинаться с `http` |

### Что проверять

| Аргумент | Что делает |
|---|---|
| `--technique LETTERS` | техники: `B`, `E`, `U`, `T`; по умолчанию `BEUT` |
| `--level N` | 1 — GET и путь, 2 — плюс формы, куки и очередь, по умолчанию 2 |
| `--crawl` | обходить ссылки своего хоста |
| `--max-pages N` | лимит страниц при обходе, по умолчанию 10 |
| `--no-recon` | не проверять заголовки, куки и типовые файлы |
| `--tamper LIST` | тамперы через запятую: `space2comment,randomcase,versioned` |
| `--threads N` | потоков для очереди ссылок, по умолчанию 3 |

### Отчёты

| Аргумент | Что делает |
|---|---|
| `--json FILE` | сохранить полный результат в JSON |
| `--html FILE` | сохранить HTML-отчёт |

При использовании `-m` значение `--url` формально всё равно обязательно, но не сканируется: список целей берётся из файла. Строки без `http` в начале (регистр важен) игнорируются. Если в файле не окажется ни одного URL, сканер просто завершится без проверок.

## Техники

| Буква | Техника | Что отправляет | Как принимает решение | Подтверждение |
|---|---|---|---|---|
| `B` | boolean-blind | `' AND '1'='1` / `' AND '1'='2` и варианты с кавычками | разница длины ответов больше `max(50 байт, 5% базового тела)` | нет, эвристика |
| `E` | error-based | кавычки, `'--`, `')`, `OR '1'='1`, URL-кодированные варианты | сигнатура ошибки MySQL, PostgreSQL, MSSQL, SQLite, Oracle или generic; либо новый статус 500 | да, повторный запрос |
| `U` | union | `' ORDER BY 1--` … `' ORDER BY 10--` | ошибка на `ORDER BY N` означает, что колонок `N-1` | да, по ошибке |
| `T` | time-based | `SLEEP(5)`, `pg_sleep(5)`, `WAITFOR DELAY`, `BENCHMARK` | ответ пришёл не раньше чем через 4 секунды | нет, эвристика |

По умолчанию включены все четыре: `--technique BEUT`. Неизвестные буквы игнорируются. Можно оставить только быстрые:

```sh
python -m sqliprobe.cli --url "https://your-site.example/item?id=1" --consent --technique EU
```

Техника `T` медленная по своей природе: пять time-пейлоадов с порогом в пять секунд плюс задержки. На локальном стенде это занимает около полуминуты.

Error-based — самая надёжная техника: находка подтверждается вторым запросом. Boolean и time-based — эвристики, они могут ошибаться на динамических страницах и медленных ответах. Union ограничен десятью колонками: если их больше, находка не появится.

## Уровни

| Уровень | Что проверяется |
|---|---|
| `1` | GET-параметры целевой ссылки и числа в пути |
| `2` (по умолчанию) | плюс POST-формы, куки и очередь найденных ссылок с параметрами |
| `3` | сейчас работает так же, как `2`: отдельной логики для него в коде нет |

Очередь ссылок проверяется уже на уровне 2. `--crawl` только собирает ссылки в пределах своего хоста; проверка очереди всё равно включается уровнем 2 и выше. `--threads` влияет только на очередь, а не на отдельные параметры одной страницы.

## Тамперы и WAF

Тамперы применяются только к error-based пейлоадам и только вторым проходом: сначала сканер пробует обычные пейлоады, и если ошибки не нашёл, повторяет с искажениями.

| Тампер | Что делает |
|---|---|
| `space2comment` | заменяет пробелы на `/**/` |
| `randomcase` | случайно меняет регистр букв |
| `versioned` | оборачивает ключевые слова в `/*!50000...*/` |

```sh
python -m sqliprobe.cli --url "https://your-site.example/item?id=1" --consent --tamper space2comment,randomcase
```

WAF-детект — информационный. Он смотрит на заголовки `Server`, `cf-ray`, `cf-mitigated`, `x-sucuri-id`, `x-protected-by` и на реакцию сервера на кавычку. В отчёт попадает имя WAF и пометка «режет кавычки», если запрос с кавычкой получил 403, 406, 429, 451, 501 или 503, а обычный запрос — нет.

Тамперы — мини-набор, а не гарантированный обход. Если WAF режет запросы, сканер может не увидеть дыру; это ограничение метода, а не доказательство чистоты.

## Отчёты

Консольный отчёт:

```
target: http://127.0.0.1:8765/item?id=1 (base http 200)
[error-based] param=http://127.0.0.1:8765/item?id=1 :: id mysql payload='
[boolean-based] param=http://127.0.0.1:8765/item?id=1 :: id payload=' AND '1'='1 / ' AND '1'='2
```

Если находок нет:

```
sqli: ничего. либо чисто, либо waf съел пейлоады.
```

JSON содержит цель, базовый статус, находки, recon, WAF, выбранную технику и уровень:

```json
{
  "url": "https://your-site.example/item?id=1",
  "base_status": 200,
  "findings": [
    {
      "param": "https://your-site.example/item?id=1 :: id",
      "type": "error-based",
      "payload": "'",
      "dbms": "mysql",
      "status": 200,
      "confirmed": true
    }
  ],
  "recon": [{"item": "missing security header: content-security-policy"}],
  "waf": {"waf": null, "blocked": false},
  "technique": "BEUT",
  "level": 2
}
```

HTML-отчёт — простая таблица находок и список recon. Он не заменяет JSON, если результат нужно обрабатывать автоматически.

| Код | Значение |
|---|---|
| 0 | проверка завершена, даже если найдены инъекции |
| 1 | ошибка выполнения: цель не отвечает, неверный URL и т.п. |
| 2 | нет `--consent` или ошибка аргументов |
| 130 | остановлено через Ctrl+C |

Важно: код возврата не сигнализирует о находках. Для автоматизации смотрите JSON и поле `findings`, а не код выхода.

При `-m` с несколькими целями `--json` и `--html` перезаписываются для каждой цели: останется отчёт только по последней. Для нескольких целей сохраняйте вывод вручную или обрабатывайте результаты по одному.

## Стенд для проверки

В репозитории есть локальный сервер с намеренно уязвимой логикой. Он не требует базы данных и работает на `127.0.0.1:8765`.

```sh
# терминал 1
python test-server.py

# терминал 2
python -m sqliprobe.cli --url "http://127.0.0.1:8765/item?id=1" --consent --delay 0.1
```

Стенд показывает все четыре техники:

- `error-based` — любой ответ с кавычкой содержит SQL-ошибку MySQL;
- `boolean-based` — `1=2` даёт короткий ответ «no rows»;
- `union-based` — `ORDER BY 4` уже ломает запрос, значит колонок три;
- `time-based` — `SLEEP` в параметре задерживает ответ на шесть секунд.

Есть также `/news/5` для числа в пути и POST-форма `/login` для проверки форм. Стенд слушает только localhost и не предназначен для выхода в сеть.

## Что сканер не делает

- не дампит таблицы, не выгружает данные и не выполняет команды на сервере;
- не подбирает пароли и не обходит авторизацию;
- не эксплуатирует найденную инъекцию — только сообщает, где она есть;
- не гарантирует, что сайт чист: WAF, нестандартные параметры, слепые и хранимые инъекции могут остаться незамеченными.

Это принципиальная граница: sqliprobe — детектор, а не фреймворк для атаки.

## Архитектура

| Путь | Назначение |
|---|---|
| `sqliprobe/cli.py` | аргументы, баннер и проверка согласия, bulk-режим, запуск отчётов |
| `sqliprobe/scanner.py` | ядро: базовые ответы, техники, формы, куки, очередь, потоки |
| `sqliprobe/crawler.py` | HTML-парсер: ссылки, POST-формы, числовые сегменты пути |
| `sqliprobe/payloads.py` | наборы error-, boolean-, time- и union-пейлоадов |
| `sqliprobe/tampers.py` | `space2comment`, `randomcase`, `versioned` |
| `sqliprobe/waf.py` | определение WAF и блокировки кавычек |
| `sqliprobe/fingerprints.py` | сигнатуры ошибок MySQL, PostgreSQL, MSSQL, SQLite, Oracle и generic |
| `sqliprobe/recon.py` | заголовки, куки, `.git/HEAD`, `.env`, robots и sitemap |
| `sqliprobe/report.py` | консоль, JSON и HTML |
| `test-server.py` | локальный стенд с фейковой дырой |
| `docs/LEGAL.md` | правовые ограничения |

Поток данных:

```
cli -> scanner
         ├─ waf.detect
         ├─ GET-параметры / путь / POST-формы / куки / очередь
         ├─ payloads + fingerprints + tampers
         └─ recon
     -> report (console / json / html)
```

## Ограничения

- **Уровень 3 пока не отличается от второго.** Очередь ссылок проверяется уже на уровне 2; отдельной ветки для 3 в коде нет.
- **`--url` обязателен даже с `-m`.** Значение при этом не сканируется: цели берутся из файла, но без флага argparse не пропустит запуск.
- **Bulk не изолирован по целям.** Ошибка на одном URL прерывает весь прогон, а уже собранные результаты не печатаются. Отчёты по нескольким целям перезаписывают один и тот же файл.
- **Код 0 не означает «чисто».** При завершённом сканировании он возвращается и с находками. Ориентируйтесь на JSON.
- **GET-формы не проверяются.** Краулер их находит, но сканер тестирует только POST-формы, GET-параметры URL, числа в пути и куки.
- **Только серверный HTML.** JavaScript не исполняется, поэтому ссылки и формы, появившиеся после рендера, сканер не увидит.
- **Union ограничен десятью колонками.** Если `ORDER BY` не ломается до 10, находки не будет.
- **Boolean и time-based — эвристики.** Динамическая вёрстка, кэш и медленный ответ могут дать ложное срабатывание. Error-based подтверждается повтором, остальные — нет.
- **Тамперы только для error-based.** Для boolean, union и time они не применяются; обход WAF не гарантирован.
- **Задержка не везде.** `--delay` выдерживается между проверяющими запросами, но WAF-проба, recon и обход страниц идут своим темпом.
- **Нет авторизации и прокси.** Сканер не логинится в приложение, не проходит многошаговые формы и не поддерживает прокси или произвольные заголовки.
- **Нет автотестов.** Проверка — локальный `test-server.py` и ручные прогоны.

## Разработка

```sh
git clone https://github.com/palychdev/sqliprobe
cd sqliprobe
pip install -r requirements.txt
python -m compileall -q sqliprobe test-server.py
```

Структура простая: новые пейлоады добавляются в `payloads.py`, сигнатуры СУБД — в `fingerprints.py`, тамперы — в `tampers.py`. Логика обхода и проверки точек живёт в `scanner.py`, разбор HTML — в `crawler.py`.

Автоматических тестов нет: после изменений запускайте `test-server.py` и проверяйте, что все четыре техники по-прежнему срабатывают на локальной дыре.

В России это прежде всего ст. 272 УК РФ (неправомерный доступ к компьютерной информации) и ст. 274. В США и ЕС — CFAA и аналогичные законы. «Я просто проверял» не является оправданием. Если вы нашли дыру на чужом сайте случайно — не продолжайте проверку, а сообщите владельцу.

Инструмент не выполняет эксплуатацию и не выгружает данные, но сам факт отправки SQL-пейлоадов на чужой ресурс может нарушать закон и условия программы. Ответственность за использование лежит на пользователе. Полный текст — в [docs/LEGAL.md](docs/LEGAL.md).
